# Correctness and Counterexample Notes

These concise arguments accompany the executable traces generated by the **DSA Demonstrations**
tab or `org.ugoptimizer.evidence.CorrectnessEvidenceMain`. The generator calls the real project
implementations and rejects a trace when its computed outcome disagrees.

## Binary Search loop invariant

Before every iteration, if the target occurs in the sorted input, at least one occurrence lies in
the closed interval `[low, high]`. Comparing the middle value discards only a half whose values
cannot equal the target. A match is therefore valid, while termination with `low > high` proves no
candidate remains. The interval strictly shrinks, so the loop terminates in `O(log n)` time.

Counterexample to omitting the sorted precondition: in `[2, 3, 1]`, searching for `1` inspects `3`
and then `2`, returns absent, although `1` is present at index 2. This is why the efficiency lab
sorts a cloned input and verifies `BinarySearch.isSorted` before timing.

## Merge Sort induction

Base case: an interval of zero or one element is sorted. Inductive step: assume both recursively
sorted halves are correct. During merge, the smaller front element is the smallest unconsumed
element of either half, so appending it preserves sorted output. When one half empties, appending
the already-sorted remainder is safe. Thus the complete interval is sorted by induction.

## Greedy assignment invariant and limitation

After candidate `i`, the retained resource is the minimum eligible candidate among positions
`0..i` under `(response time, workload, resource ID)`. An ineligible candidate preserves the
invariant; a smaller eligible key replaces the current best. At the final index, the retained
candidate is therefore the best eligible resource for that one request.

Counterexample to global optimality: suppose fast unit F takes 2 minutes to request A and 3 to B,
while unit S takes 3 minutes to A and 100 to B. Processing A first greedily assigns F, forcing S to
B for total 102. Assigning S to A and F to B totals 6. The implementation deliberately solves one
current assignment, not the multi-request global matching problem.

## Dynamic programming recurrence

For item index `i` and capacity `c`, the table stores the best benefit available from that suffix.
If item `i` is too costly, exclusion is the only feasible state. Otherwise the recurrence compares
exclusion with the item's benefit plus the already-correct state for the remaining capacity.
Induction over decreasing item index proves every state optimal. Reconstruction follows exactly
the stored winning decisions, so its selected cost is feasible and its benefit equals the optimum.

## Graph and MST checks

Dijkstra settles the smallest current tentative distance from the custom heap. Non-negative edge
weights mean no later route can reduce a settled vertex, and each relaxation preserves the best
known path through settled predecessors. Kruskal accepts an edge only when the custom disjoint set
reports different components, preventing cycles; the cut property makes the smallest eligible
edge safe. The evidence graph runs both Prim and Kruskal and requires identical total MST weight.
